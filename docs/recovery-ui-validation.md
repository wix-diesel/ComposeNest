# 復旧選択UIの検証記録

Issue #43 の復旧画面は、明示的な実体再確認で得た Core の許可選択だけを表示する。
再確認は読取専用であり、ボタン操作や時間経過を成功の根拠にしない。

## 実装・検証済み

- 固定された Engine、資源の所有、保存領域、生成設定、CLI 終了の確認と保留理由の表示。
- 同一 Operation の再試行・観測結果の確定・安全な終了。
- 完全な候補ポート差分と旧ポートへの復帰確認。候補提案だけでは適用しない。
- 外部編集のファイル差分 hash 確認、退避・保存設定への復帰、受付応答喪失時の読取専用再照会。
- 過去の Failed と現在の Ready の独立表示。再試行でも失敗履歴を保持する。
- リビジョン競合、未終了 CLI、Missing、所有不明、接続先不一致、二重送信の障害注入テスト。
- Core/Adapter の通常 Rust テスト 295 件成功、Docker 必須テスト 3 件はローカルでは未実行。
- 終了未確認でも読取専用照合を継続し、変更の禁止は解除しない。
- 有効な別 hash の受付前拒否、未適用の Abandoned 作成・Clone の復帰選択除外。
- 日本語・最大長 requestId と独立した復帰 Operation ID、RECOVERY_HELD 前後の受付再照会。
- 削除処理の汎用終了を Core と永続化境界で拒否し、画面にも「安全に終了」を表示しない。
- Rust fmt・Clippy、IPC 契約生成検査、TypeScript 型検査・Vite build 成功。
- Operation・復旧・環境操作・削除のブラウザ回帰テスト。復旧画面はライト/ダーク、幅 1280/390 px で確認。

## 検証範囲と保留条件

ブラウザテストは Tauri IPC の障害応答を注入する。Adapter テストは既存の
偽 CLI と実ファイル・DB を使用し、実 Docker やネイティブ WebView の代用とはしない。
実 Docker の契約テストと Tauri を含む workspace 検査は CI が担当する。
Windows/macOS/Linux の実機 UI 操作による受入検証は未実施。

起動前から未解決の処理で、未完了または結果不明の CLI ステップが残る場合は、
終了したという証拠をこのセッションから取得できないため変更を保留する。
強制解除や名前だけでの資源所有判定は提供しない。
